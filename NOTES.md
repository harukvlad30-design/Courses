# Робочі нотатки

## Лабораторна робота № 2: Модель предметної області

* **Основний тип (`Course`):** створено клас із 7 змістовними властивостями та первинним ключем `Id`.
* **Вибір типів даних:**
  * `DateOnly` для `StartedOn` та `DateOnly?` для `CompletedOn` — обрано замість `DateTime`, оскільки для обліку проходження курсів важлива лише календарна дата початку та завершення навчання без прив'язки до точного часу (годин і секунд). Поле `CompletedOn` зроблено nullable (`DateOnly?`), оскільки курс може перебувати у процесі вивчення і ще не мати дати закінчення.
  * `decimal` для `Price` — обрано для точного збереження грошової вартості курсів без двійкових похибок округлення, властивих типам `double` та `float`.
  * `int` для `DurationHours` — обсяг курсу вимірюється в академічних годинах цілим числом, що дозволить у ЛР 9 коректно виконувати агрегатні SQL-обчислення (`Sum`, `Average`) у базі SQLite.
* **Рішення щодо типу-переліку (`enum`):** створено перелік `CourseStatus` (`Planned`, `InProgress`, `Completed`, `Dropped`), оскільки стан проходження курсу має суворо обмежений набір значень. Використання `enum` замість рядка унеможливлює помилки введення та спрощує подальшу фільтрацію записів.
* **Обрана особливість (Додаток Б):** експорт зведеного звіту про пройдені курси та обсяг навчання у файл із роздільниками (CSV).

## Лабораторна робота № 3: Entity Framework Core і SQLite

* **Контекст даних (`CoursesContext`):** створено клас контексту у просторі імен `Courses.Data` із набором сутностей `DbSet<Course> Courses`.
* **Перетворення типів (`OnModelCreating`):** оскільки модель `Course` містить властивість `Price` типу `decimal`, а SQLite зберігає `decimal` у текстовому вигляді, у методі `OnModelCreating` задано конвертацію `HasConversion<double>()` для забезпечення коректного сортування та агрегатних обчислень у БД.
* **Фабрика контекстів:** у `Program.cs` зареєстровано `AddDbContextFactory<CoursesContext>` із рядком підключення `"Data Source=courses.db"`.
* **Міграції:** створено початкову міграцію `Init` та розгорнуто файл бази даних `courses.db` (який виключено з репозиторію через `.gitignore`).

## Лабораторна робота № 4: Генератор сторінок CRUD

* **Пояснення п'яти ключових елементів згенерованого коду:**
  1. **Директива `@page "/courses"`:** вказує маршрутизатору Blazor URL-адресу, за якою відкривається компонент переліку. Генератор автоматично перетворив назву моделі в однині (`Course`) на множину (`courses`) згідно з правилами англійської мови.
  2. **Відсутність директиви `@rendermode`:** означає, що компонент працює в режимі статичного серверного відтворення (Static SSR). Сторінка формується на сервері під час HTTP-запиту і передається браузеру як звичайний HTML без відкриття постійного WebSocket-з'єднання SignalR, тому переходи між сторінками пагінації реалізовано через звичайні посилання з параметрами запиту (`?page=2`), а не події `@onclick`.
  3. **`@inject IDbContextFactory<Courses.Data.CoursesContext> DbFactory`:** впроваджує через механізм Dependency Injection зареєстровану в `Program.cs` фабрику контекстів даних. У методі `OnInitialized` фабрика створює окремий ізольований екземпляр `CoursesContext` для поточного запиту, а інтерфейс `IAsyncDisposable` гарантує його коректне закриття після завершення роботи сторінки.
  4. **Параметр `Items` компонента `QuickGrid`:** приймає запит типу `IQueryable<Course>` (`context.Courses.OrderBy(...).Skip(...).Take(...)`), а не завантажений у пам'ять список. Завдяки цьому Entity Framework Core транслює операції сортування (`OrderBy`) та відбору сторінки (`Skip`, `Take`) безпосередньо у SQL-запит до бази даних SQLite, завантажуючи лише 10 потрібних записів замість усієї таблиці.
  5. **Атрибут `[SupplyParameterFromQuery]` на властивості `Page`:** дозволяє компоненту автоматично зчитувати значення параметра `page` з рядка адреси URL (наприклад, із `courses?page=2`). Якщо параметр у посиланні відсутній або некоректний, обчислювана властивість `CurrentPage` повертає `1` за замовчуванням.
